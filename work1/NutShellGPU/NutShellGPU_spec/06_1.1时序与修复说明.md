Author: Di Zhao (zhaodi@ucas.ac.cn), Trae CN

References: Tor M. Aamodt, Wilson W. Lun Fung, Timothy G. Rogers, General-Purpose Graphics Processor Architecture, Morgan & Claypool, 2018

本册说明 C++ 周期模拟器的实际实现。所有延时为可配置的模拟值。

## 1. 架构与提交规则

保留 NTAS1、32-lane warp、CTA 驻留与补发、NSM、SIMT 栈及 SP/SFU/DP/BRU/LSU 五类执行单元。默认仍为 4 个 cluster、每 cluster 4 个 NSM。

每个周期依次处理到期写回、执行状态、操作数收集、取指/译码/发射，以及 CTA 退休与补发。前端取指、译码、发射在同一 tick 内衔接，不分别增加独立流水线寄存器延时。I-Cache 当前假定命中。

发射只创建 collector，收集只占用读端口并分配执行槽。**只有写回阶段调用功能语义，才改变寄存器、谓词、内存、PC 和 SIMT 栈。** `ready_cycle` 之前不能读取新结果，写回端口不足时继续保留执行槽。

当前每 warp 最多一条未提交指令。`pending_commit` 是顺序依赖互锁，覆盖 RAW、WAW、WAR、谓词、累加目标、宽寄存器对及控制流依赖。它也会阻止同 warp 的独立指令重叠，属于保守模型；不等同于支持寄存器级乱序调度的完整记分牌。不同 warp 可以在不同流水段和执行单元中并行。

分支、BAR、MEMBAR、EXIT 也经过 collector 和执行槽；不会越过同 warp 的旧访存。屏障沿用按 CTA、屏障 ID 和代次维护的同步语义。全局内存并发数据竞争的结果不作跨调度顺序的一致性保证。

## 2. 指令延时和吞吐

| 指令类别 | 默认执行延时 | 配置字段 |
|---|---:|---|
| MOV/MOV32I/NOP/S2R | 1 周期 | move_latency |
| 一般整数/逻辑等 SP 指令 | 2 周期 | integer_latency |
| IMUL/IMAD | 4 周期 | imul_latency |
| IDIV/IREM | 32 周期 | idiv_latency |
| FADD/FSUB/FMUL/FFMA | 4 周期 | sp_latency |
| SHFL/VOTE | 4 周期 | shuffle_latency |
| SFU | 8 周期 | sfu_latency |
| DP | 8 周期 | dp_latency |
| 控制流 | 1 周期 | branch_latency |
| BAR | 控制流延时 + 屏障恢复延时 | branch_latency、barrier_resume |
| LDC | 常量读的基础延时 | l1_hit |
| LD/ST/LDU/宽访存/原子 | 由访存路径决定 | 见下一节 |

执行延时与启动间隔分别建模。有效启动间隔不小于 `ceil(32 / 单元 lane 数)`；SP、SFU、DP 的配置间隔也会约束发射。每类算术/控制流水线默认 16 个执行槽，LSU 默认 32 个槽。

每 NSM 默认每周期一个统一提交端口，所有指令类型竞争它；这不是逐 lane 的寄存器写端口模型。到期较早的指令优先提交。

`core_clock_ghz` 默认 1.0。纳秒参数按 `ceil(ns × core_clock_ghz)` 换算，最小一周期。总周期不等于宿主机墙钟时间。

## 3. 寄存器 bank

GPR bank 编号为 `reg % rf_logical_banks`，默认四个 bank，每 bank 每周期一个读端口。同一 collector 内同一源寄存器只读取一次，重复使用采用广播；不同 collector 竞争同一组端口。仲裁起点按周期轮询。

未获得端口的源保留到下周期。源全部读完后，还要等待执行单元的启动间隔与空闲槽。谓词使用独立逻辑读路径，不加入 GPR bank 冲突。常用指令列出源集合；部分复合指令使用保守集合，因此其 bank 成本可能偏高。

## 4. 内存层次

- 全局访问按扇区合并，默认扇区 32 字节。跨扇区访问覆盖全部相关扇区。
- Shared 默认 32 个 bank、每 bank 4 字节；同字读取广播，不同字同 bank 分轮服务。写入或原子同址不视为读取广播。
- L1/L2 使用有限容量组相联 tag、逐扇区完成时间及 LRU 替换。未完成填充不能计为普通命中；请求可以等待已预约的填充时间。
- 每 NSM 的 L1 MSHR 和每 L2 slice 的 MSHR 数有限，资源用尽则顺延预约。不能无限分配在途请求。
- LDU/CG 绕过 L1；CV 绕过两级缓存；store 采用写穿、绕过缓存分配；其余缓存提示使用默认策略。CS/LU 不实现独立替换策略。
- NoC 使用每内存分区的共享带宽预约，按 flit 大小、链路及路由延时计时。请求和返回均按扇区传输量计费；不是逐 flit 拓扑路由或真实虚通道状态机。
- DRAM 保留通道、bank、开放行、行命中/未命中及总线占用，按请求预约顺序服务。行未命中加入 tRP+tRCD。不实现 FR-FCFS 重排，也未独立建模刷新、tRAS/tRC 等全部约束。
- 原子更新在功能提交时不可分割，并加入原子模拟延时；当前支持 32 位原子操作，其他宽度明确返回错误；不模拟完整 L2 原子流水结构。
- 常量读采用基础延时和地址分散成本，不单独模拟常量缓存替换。

缓存只存时序元数据，实际数据由功能层唯一维护；加载和存储在提交时才访问数据。主机装载不计入周期，连续 kernel/样本保留 tag 状态。需要冷缓存实验时应创建并初始化新的 CycleSim 实例。

存储路径采用资源预约时间戳，`tick` 仍逐周期推进流水线并在到期时写回。旧头文件中的 PRT/WDB/Flit/DRAMBank 等结构保留作接口参考；1.1 的实际访存状态由 `TimingCache`、MSHR 完成时间和通道预约表维护，不能把这些保留结构视为全部已启用。

## 5. 正确性修复对应关系

修复 ID、文件和函数见根目录 `CHANGELOG.md`。新增的 flat/宽访存修复统一地址转换与边界验证；目的寄存器覆盖地址寄存器时，先保存地址并读取所有字，再提交各目的字。

`run(n)` 的预算为本次增量；`run(0)` 不设周期上限。超预算返回 `ERR_DEADLOCK`，未完成状态仍保留，允许后续继续运行。此错误码也用于预算耗尽，并不单独证明程序存在逻辑死锁。调用方必须检查返回值和 `is_done()`。

## 6. 统计口径

输出 schema 为 `NutShellGPU-stats-1.1`。`cycles` 为全芯片模拟周期，`instructions` 为发射的 warp 指令数；IPC 是两者之比，多 NSM 时可超过 1。占用率为每 NSM 活跃 warp 数的时间平均。

`rf_bank_conflict_cycles` 累加出现冲突的 NSM 周期；`rf_conflict_stalls` 为未获端口的源请求次数。`serial_dependency_stalls`、`sb_wait` 是调度扫描中遇到互锁 warp 的次数，不是全芯片唯一停顿周期。各停顿计数可重叠，不能相加视作总周期。

`l1_access_lines` 为兼容字段，1.1 实际统计合并后的扇区请求；`memory_sectors` 为明确同义字段。`l1_hits` 为已完成命中，`l1_pending_merges` 为等待在途填充；`l2_hits` 包含等待已预约填充的情形。DRAM busy 和 NoC stall 为累积服务/预约量，可能大于总周期。GB/s 按字节/周期乘模拟 GHz 计算。

`stall_cycles` 累加未成功发射的 NSM 周期，包括空闲 NSM，不能当作单个活跃 warp 的停顿时长。保留的 I-Cache miss、WDB、部分 replay 和 `unsupported_timing_ops` 等兼容字段当前不驱动机制，不应将其零值视为完整结构的实测结论。

源文件不依赖外部数学加速库。独立参考框架仅用于生成测试期望值。
