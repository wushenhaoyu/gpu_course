# Newton NutShellGPU 架构规格书（总览与配置参数）

> 教材版通用图形处理器（GPGPU）规范 · 第 0 册
> 架构代号：**Newton**　芯片型号：**NutShellGPU**　计算核心：**NSM**（Newton Streaming Multiprocessor）
> 硬件指令集：**NTAS1**（Newton Thread Assembly，固定 64 位编码）
> 虚拟指令集：**NPTX1**（驱动/汇编器向下编译为 NTAS1）
> 计算能力版本号：**NC 1.0**
> 版本：Spec 1.0　基线微结构定位：教科书"基线 GPU"（基于栈的 SIMT 再收敛、单发射、in-order scoreboard、operand collector、指令 replay），总体对标 NVIDIA Fermi/Kepler 时代的已公开资料，不含图形管线（无光栅/纹理采样），仅保留 compute。

## 1. 模拟器组成

`FuncSim` 执行 NTAS1 指令语义，维护寄存器、线程掩码、SIMT 栈、存储空间、屏障和 CTA 状态。`CycleSim` 调用相同功能实现，并维护流水线、执行延迟、寄存器 bank 端口及存储访问的完成时间。

两者读取相同指令编码和内核元数据。`Config` 保存拓扑、资源数量和模拟延迟。1.1 的已实现时序行为与保留接口见第 06 册。

## 2. 系统级视图

NutShellGPU 是独立（discrete）GPU，通过 PCIe 与主机 CPU 相连。主机负责：分配/初始化数据、把代码与启动参数经驱动写入 GPU 可访问内存、向命令队列写入 launch 命令、取回结果。GPU 本身不承担 I/O 与 OS 服务。

```

                system memory (DDR)            PCIe Gen3 x16
        +-----------------------------+        拷贝/命令/完成中断
        |  runtime  |   driver       |
        +-------------+---------------+
                      |  command queue / doorbell
 =====================|=========== NutShellGPU ==================================
                      v
              +----------------+
              | Command Proc / |     全局工作分发引擎（CTA Work Distributor）
              | Work Distrib.  |
              +-------+--------+
                      | CTA 分派（round-robin + 资源约束）
      +---------------+-----------------------------------+
      |               |            4 个 GPC               |
      |   +-----------+-----------+   +---------------+   |
      |   |  NSM0 NSM1 NSM2 NSM3  |...| NSM12..NSM15  |   |   16 个 NSM
      |   +-----------+-----------+   +---------------+   |
      |                   |                               |
      |             +-----+------+   片上互连：全交叉开关（crossbar）
      |             |  NoC XBAR  |   地址交织 256B 粒度，6 路分片
      |             +--+--+--+--+                           |
```

| 项目 | NutShellGPU 参数 |
|---|---|
| 核心时钟频率 `gpu_clock` | **1000 MHz**（周期 = 1.0 ns，时序模型统一以此时域计） |
| NSM 数量 | **16** |
| GPC 数量 | 4（每 GPC 4 个 NSM；compute 负载下 GPC 仅做时钟/电源域划分，不影响功能） |
| 每 NSM warp 槽位 | **64**（最多 2048 线程驻留） |

| 每 NSM FP64 流水线 | 16 lanes（双精度吞吐为 FP32 的 1/2） |
| 每 NSM Load/Store 单元 | 1 个 LSU（32 lane 地址生成，1 条访存指令/周期接收） |
| 寄存器堆（每 NSM） | **256 KiB = 65 536 个 32 位物理寄存器**，4 个单端口逻辑 bank |
| 每线程架构寄存器 | R0..R254（255 个）+ 常量零寄存器 RZ；谓词 P0..P6 + 恒真 PT |
| Shared + L1 统一 SRAM | **64 KiB/NSM**，可配置切分，默认 48 KiB shared + 16 KiB L1D |
| L1 指令 cache | 8 KiB，4 路，128 B line |
| L1 常量 cache | 8 KiB（只读，warp 内同址广播） |
| Memory Partition 数 | **6** |
| 每 MP 的 L2 slice | 2 × 128 KiB（全片 L2 共 **1536 KiB**） |
| 片外内存 | 6 个 GDDR5 通道，每通道 32-bit / 8 bank / 1 GiB |
| 片外带宽 | 5.0 GT/s/pin × 32 bit × 6 = **120 GB/s**（32 B burst atom） |
| 地址交织粒度 | 256 B，XOR 折叠到 6 个 MP |
| PCIe | 功能模型：host↔device 显式 memcpy（命令队列、doorbell）；不计带宽时序，可配拷贝延迟 |
| 内核并发 | 基线：同一时刻全片 1 个 grid；硬件可驻留多 kernel 命令但顺序执行（多 kernel 并发为可选扩展，见 05 册附录 C） |
| 抢占 | 无（CTA 一旦分派不可抢占，运行到结束才释放资源） |
| 一致性模型 | 弱序；L1 不跨 NSM 一致；L2 为全局共享一致点；`MEMBAR` + `BAR.SYNC` + 原子操作提供顺序 |

**理论峰值（参考核算）**

- FP32：16 NSM × 32 lanes × 1 warp/周期 × 2 ops（FMA）× 1 GHz = **1.024 TFLOPS**
- INT32 MAD：同上 **1.024 TOPS**
- FP64：16 × 16 × 2 × 0.5 × 1 GHz = **0.256 TFLOPS**
- 片外带宽 120 GB/s；典型 FP32 FMA 每字节访存比（roofline 拐点）≈ 8.5 FLOP/byte

## 4. 顶层功能模块

### 4.1 命令处理器 / 全局工作分发引擎（Command Processor & CTA Work Distributor）

1. 驱动在设备内存中建立：kernel 代码段、参数段（≤ 4 KiB）、launch 描述符，把 launch 命令写入命令队列并敲 doorbell。
2. 命令处理器读取 launch 描述符（见 01 册 §5），创建 grid：共 `Ncta = Gx·Gy·Gz` 个 CTA，CTA id 按 x 最快展开。
3. 工作分发引擎每周期扫描各 NSM 的资源空闲情况，按 **round-robin** 顺序把下一个 CTA 分派给能装下它的 NSM；若全片无可用 NSM，停顿等待。资源以 **CTA 为粒度整体认购**：warp 槽、物理寄存器、shared 空间在分派时一次性预留。
4. CTA 不可抢占；CTA 内所有 warp 执行 `EXIT` 后，NSM 上报完成并归还资源，分发引擎才可分派新 CTA。
5. 最后一个 CTA 完成后，向主机写完成字（completion token），功能模拟器中 launch 调用返回。

### 4.2 NSM（Newton Streaming Multiprocessor）

见 03 册。要点：SIMT 前端（Fetch/I-Cache/Decode/I-Buffer/Scoreboard/Issue/SIMT-Stack）+ SIMD 后端（Operand Collector/SP/SFU/LSU/WB），三个调度循环。

### 4.3 片上互连（NoC）

见 04 册 §4。基线：全交叉开关，2 条虚通道（request / response），路由器流水 1 级、链路 1 周期；包由若干 flit 组成。功能模拟器可把 NoC 退化为"按地址直连 MP"的函数调用。

### 4.4 Memory Partition（MP）

每个 MP 含：2 个 L2 slice（各自独立 tag/data array，顺序处理入站请求）、1 个 FB 访存调度器（FR-FCFS）、1 个 ROP 原子单元（含小容量原子操作 cache）、1 个 GDDR5 通道接口。

| FP64（16 lanes） | 8 | 1 warp / 2 周期 |

| DRAM 行未命中（precharge+activate） | 400 + tRP + tRCD ≈ 424 | — |

## 6. 存储空间一览

| 空间 | 可见性 | 生命周期 | 位置 | 每 CTA/线程容量 | 缓存策略 |
|---|---|---|---|---|---|
| **Global** | 全 grid + host | 跨 kernel，host 分配 | 设备 DRAM | host 分配，默认共 6 GiB | L2 全缓存；L1D 默认只缓存只读/ local 数据 |
| **Local**（寄存器溢出/栈） | 单线程 | kernel | DRAM（经 L1/L2） | 每线程最多 512 KiB 虚拟窗口 | L1D：write-back + write-allocate |
| **Shared** | CTA 内 | CTA | NSM 内 SRAM | 默认 48 KiB/CTA（多 CTA 瓜分 64 KiB） | 软件管理，32 bank |
| **Constant** | 全 grid（只读） | kernel | DRAM + 8 KiB/NSM cache | 参数区 ≤ 4 KiB；常量表 ≤ 64 KiB | warp 同址一次取指广播 |
| **Param** | kernel 入参 | kernel 调用 | constant bank 0 | ≤ 4 KiB | 经常量 cache |
| **Instruction** | — | kernel | DRAM + I-Cache + L2 | 代码段 ≤ 每 kernel 1 MiB | I-Cache/L2 |

平面（flat）64 位虚拟地址窗口划分（供 `CVTA` 与 LD/ST 的 flat 模式使用，软件模拟器必须照此实现）：

```
0x0000_0000_0000_0000 .. 0x0000_00FF_FFFF_FFFF   Global   (1 TiB 窗口)
0x0000_0100_0000_0000 .. 0x0000_01FF_FFFF_FFFF   Shared   (按 CTA 基址重定位)
0x0000_0200_0000_0000 .. 0x0000_02FF_FFFF_FFFF   Local    (按 warp/lane 重定位)
0x0000_0300_0000_0000 .. 0x0000_03FF_FFFF_FFFF   Constant
```

所有地址小端（little-endian）。虚拟→物理转换由 MMU 完成；基线使用**恒等页映射**（页大小 64 KiB，单应用、无 TLB 未命中开销，TLB 为可选统计结构）。

## 7. 数值与异常语义

- 整数：32 位补码，加减乘自然回绕；移位量按 &31（32 位）/&63（64 位）掩码；除零返回 0（不陷入）。
- FP32/FP64：IEEE 754，默认舍入就近偶数（可由指令后缀 `.RM` 改）；**不刷新 subnormal**（软件模拟器必须实现次正规数）；NaN 传播规则遵循 IEEE；`FSET`/`SETP` 比较中 NaN 视为无序。
- 不实现 FP 异常陷入；整数溢出不陷入（饱和指令后缀 `.SAT` 例外）。
- 所有 warp 指令按 lane 独立产生结果；掩码为 0 的 lane：不读存储、不写寄存器、不产生副作用（谓词执行与 SIMT active mask 取**逻辑与**）。
- 不支持抢占、不支持页故障服务（非法地址访问产生设备异常，见 05 册 §8 错误模型）。

## 8.1 关键派生约束（分派 CTA 时检查）

一个 CTA 请求 `R` 个 32 位寄存器/线程、`B` 线程、`S` 字节 dynamic shared memory、`P` 个 barrier slot，则：

```
warps_needed      = ceil(B / 32)
regs_needed       = R * B                         （64 位寄存器占 2 个槽）
smem_needed       = static_smem + S
可驻留 NSM 当且仅当：
  cur_warps + warps_needed <= 64
  cur_ctas  + 1             <= 16
  cur_regs  + regs_needed   <= 65536
  cur_smem  + smem_needed   <= smem_size_bytes
  cur_barriers + P          <= 16
```

**占用率（occupancy）** = 驻留 warp 数 / 64。两个模拟器都要在统计中输出每个 kernel 的实际占用率。
