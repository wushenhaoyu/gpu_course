# 存储系统微结构规格（第 4 册）

> 本册定义 NSM 内一级存储（shared/L1D/I-Cache/常量）、片上互连、Memory Partition（L2/ROP/FB）与 GDDR5 通道的可仿真结构。教材第 4 章的组织为本册蓝本。功能模拟器只实现带【F】标记的数据路由与正确性语义，时序全部忽略。

---

## 1. NSM 一级存储总体组织

```
   collector/BRU
       │ 一条 warp 访存指令：{32 lane 地址[], 宽度, 空间, hint, 数据(ST), 谓词后 exec mask}
       v
 +------------------+
 | Load/Store Unit  | 地址生成（含 flat 译码）、coalescing、replay 队列(16)
 +--------+---------+
          │ 规范化后的 sector 访问集合（每拍至多送 1 个 line 组）
          v
 +------------------+      +-----------------+
 |     Arbiter      |<---->| Pending Request |
 | 接受/拒绝/replay |      | Table (32 项)   |
 +---+----------+---+      +-----------------+
     |          |
     v          v
 +--------+  +----------------------+
 |Tag Unit|  | MMU（虚→物，恒等分页） |
 +---+----+  +----------------------+
     | 地址交叉开关
     v
 +--------------------------------------------------------------+
 | Data Array：64 KiB 统一 SRAM                                   |
 |  - shared 分区：32 bank × 32bit，直接映射（默认 48 KiB）       |
 |  - L1D 分区：16 KiB，4 路，128B line × 4×32B sector（VI/VT）  |
 +---+----------------------------------------------------------+
     │ 数据交叉开关（仅活跃 lane 写 RF）
     v
 +------------------+        +------------------+
 |  Fill Unit       |<-------|  Write Buffer 16 |
 | (subid→PRT 查表) |        +------------------+
 +--------+---------+                  │ ST/WT/脏行
          │ 经 MMU → NoC（请求带 subid）│
          v                            v
        XBAR ←────────────── response / writeback
```

非停滞接口：LSU 与 cache 之间**没有反压停顿通路**，资源不足一律返回"拒绝"并由 LSU replay（03 册 §9）。

## 2. 【F】Shared memory：bank 规则与 replay

### 2.1 地址映射

- 容量默认 48 KiB/NSM，多 CTA 驻留时按 CTA 槽划分基址（地址空间内每 CTA 从 0 编址，出口加基址）。
- 32 个 bank，每 bank 宽 32 bit（4 字节）、1R1W 端口；**bank 号 = (shared 内字节地址 / 4) mod 32**（与 lane 无关）。
- 一次 warp 访问每拍至多每 bank 服务一次。

### 2.2 冲突判定（对一条 warp 指令的活跃 lane 集合）

1. 展开每 lane 的 `(addr, size)`；按自然对齐访问（size=8 需 8B 对齐，否则 `ERR_MISALIGNED_ADDR`）。
2. 对每 lane 请求占用的 bank 集合：32 位访问占 1 bank，64 位占相邻 2 bank。
3. 一个 bank 在一拍中：
   - 被 ≥2 lane 请求且地址**不同** ⇒ bank 冲突；
   - 被多个 lane 请求但地址**全相同** ⇒ 多播/广播：一拍读一次，返回数据广播给所有请求 lane（ST 同址同宽：合成为一次写；同址不同数据：lane 号最小者胜，确定性规则）。
4. Arbiter 贪心着色：按 lane 号递增，把与已选 lane 不冲突的 lane 放入**接受子集**，其余为 **replay 子集**；接受子集当拍执行（直接映射、无 tag 查找，延迟 2 拍后写 RF——操作数就绪起算），replay 子集进 LSU replay 队列，下一拍重新走同一流程，可继续被切分。
5. 统计：每产生一次非空 replay 子集计 `replay_smem_conflict` 一次；一个 warp 访问的拍数 = 冲突分组数（性能模型必报）。

### 2.3 与指令的关系

`LD/ST/ATOM/RED.SHARED` 走本通路；shared 原子在 Arbiter 内串行（同地址逐拍执行，天然互斥）。shared 内容**不经 NoC、不进 L2**。CTA 结束时其分区整体回收（无需写回）。

## 3. 【F】Global/Local 访存：coalescing 规则

一条 warp LD/ST 的 32 个 lane（先与 exec mask 相交）产生至多 32 个独立字节访问 `(vaddr_i, size, data_i)`。

### 3.1 规范化算法

```
1) flat 地址按窗口译码出空间（00 册 §6）；.LOCAL 追加 (warp*32+lane) 重定位
2) 对每活跃 lane 的访问，求其覆盖的 32B sector 集合：
     sec = addr >> 5；跨 sector（非对齐/大宽度）拆为 2 项
   U64/F64 自然 8B 对齐；U128 16B 对齐
3) 按 (space, sec) 分组；同组内合并 byte-enable（4 字节粒度 be[8]）
4) 同组内同地址重叠写：
   - 完全包含的 32 位同值 → 合并；
   - 同字节写不同值 → lane 最小者胜（确定性），功能结果以此为准
5) 输出 sector 请求表，按 sec 升序；标注其所属 128B line（sec>>2）
```

- **coalesced**：32 lane 全部落在同一 128B line（最好情况 1 个 line 请求、至多 4 个 sector）。
- **uncoalesced**：最坏 32 个 line 请求。
- 常量空间另有广播规则（§6）。
- LD.128/ST.128：要求 warp 内连续 lane 构成连续 16B 段，LSU 按 lane 对 (0,1)…(30,31) 合并成 16B 事务；不对齐的 lane 对导致该对 replay?——裁定：拆成两个 128 位不对齐访问按 §3.1 走 sector 合并，不报错。

### 3.2 每拍发送

Tag Unit 每拍只查 **1 个 128B line**：sector 表按 line 分组依次送入 Arbiter；同 line 的 4 sector 共享一次 tag 阵列访问。

## 4. L1D 数据 cache（统一 SRAM 的 cache 分区）

### 4.1 参数

16 KiB，4 路组相联，128 B/line（=4×32B sector，sector 有效位独立），共 32 组，LRU。**虚拟索引、虚拟标识（VI/VT）**：用 §3 的虚拟 sector 地址直接查 tag；仅在 miss 出站时经 MMU 翻译（基线页映射恒等，无 TLB 延迟）。

### 4.2 读路径（global/local LD）

```
Arbiter 每拍对一个 line 组：
  前提检查：
    - PRT 有空项？该 set 是否有可用 way（way 被未完成 miss 标 busy ⇒ associativity stall）？
    否 → 拒绝（LSU replay，replay_assoc / replay_prt_full）
  乐观调度：按命中延迟（30 拍）向流水线预约写回事件
  Tag 查找（同拍）：
    命中（所需 sector 有效位齐全）：
        数据经数据交叉开关回 RF，仅活跃 lane 写；取消错误预约不会发生（无推测）
    缺失：
        PRT 登记 §4.4；通知 LSU 该指令 mem_pending+replay；
        请求 MMU→NoC→L2（携带 subid、所需 sector 位向量、字节使能）
```

- **hits under miss**：非阻塞，其他 warp / 同 warp 后续行命中照常服务。
- 部分 sector 命中：命中 sector 立即返回，缺 sector 登记 PRT（一条指令可"半命中"，统计拆为 hit_sectors/miss_sectors）。

### 4.3 写路径（ST）

先入 Write Data Buffer（WDB，16 项，每项一条 warp store 的合并产物）。

| 数据类别 | 策略 |
|---|---|
| Global ST | **write-through + no-write-allocate**：数据送 L2；L1 中若有该 line 副本，使对应 sector tag 失效；整条 128B 被写满且全缓存行无效时直接绕过 L1 tag 阵列 |
| Local ST（溢出/栈） | **write-back + write-allocate**：miss 时先取 line（RFO，读字节使能补全），合并后进 cache，脏位置位 |
| 部分 sector 写 | 按 4 字节 byte-enable 合并；不触发整行写分配（local 仅在缺行时取一次） |
| WDB 满 | ST 指令 replay（`replay_wdb_full`） |

替换脏行（local 分区）时脏数据经 WDB→L2。

### 4.4 Pending Request Table（PRT/MSHR）

32 项：

```
PRT {
  u64   vline;                 // 虚拟 line 地址
  u8    need_sectors;          // 尚缺的 4 位 sector 向量
  u8    busy_way;              // 占用中的 way（associativity 用）
  list  waiters;              // {warp,pc,lane-sector 映射, 目标寄存器/ST 项, byte-en}
  u16   subid;                 // 出站请求在本 NSM 内的序号，随包携带
  u8    state;                 // SENT / FILLING
}
```

- 到同一 line 的后续 miss **合并**进 waiters，不重复发下游。
- 响应经 Fill Unit 返回：按 subid 查 PRT → 数据写入 busy_way 的指定 sector → **锁定该 line**，通知 Arbiter 重放 waiters；重放访问必命中，全部完成后解锁、释放 PRT。
- 缺行在 cache 中**检测到时即分配 way**（行锁）；PRT 保存该行的等待请求。

### 4.5 一致性（无硬件协议）

- L1D 之间**不互保一致**。基线策略（只缓存 local 与只读 global）在源头规避大部分问题；软件跨 CTA 共享可写数据必须经 L2 + `MEMBAR.GL`/原子。
- 同一 CTA 的 warp 共享同一 L1D：CTA 内可见性由 `BAR.SYNC` 保证（屏障释放前排空本 CTA WDB 到 L2 的顺序要求仅对 global 生效；shared 为同一 SRAM，屏障即足够）。
- CTA 结束：其 local 分区行作废；global 只读行可保留（下个 kernel 若映射不同内容，由 host 通过启动代际号（generation id）使全 L1 只读行在 kernel 边界失效——硬件维护 1 位 generation 比较即可）。

## 5. I-Cache

8 KiB / 4 路 / 128B line / LRU；物理上独立阵列，不与 L1D 争端口。8 个 MSHR；缺失经 NoC 到 L2（指令在 global 代码段，L2 正常缓存）。功能模型命中率 100%。

---

## 6. 常量 cache

8 KiB/NSM，2 路，64B line（常量无 sector 概念），只读。

- warp 内 32 lane 同地址：1 次取数广播（cache 内单端口读 + 全 lane 广播），命中延迟 30。
- warp 内多地址：按不同地址逐拍串行取（每拍 1 个地址），数量记入 `const_divergent_access`；这些访问仍各自查 cache（可能命中不同行）。
- 参数区 bank0 在 kernel 启动时预热（功能模型视为已在 cache）。

## 7. MMU 与地址映射

- 64 KiB 页，虚拟→物理基线恒等（设备物理地址 = 虚拟地址去掉空间窗口后的全局偏移；shared/local 请求在进入 MMU 前已分流，不翻译）。
- TLB 为可选统计结构（EXT-TLB）；非法地址（超出任何已分配区间/窗口）在翻译点报 `ERR_ADDR_OUT_OF_RANGE`。

### 7.1 【F】物理地址到 MP / slice / DRAM 的散列（必须逐位实现）

设 global 物理字节地址 `A`：

```
b256  = A[31:8]                         // 256B 交织块号
fold  = b256[5:0] ^ b256[11:6] ^ b256[17:12] ^ b256[23:18]
mp    = fold % 6                        // 0..5：memory partition（=GDDR5 通道）
slice = (A[7] ^ A[14] ^ b256[3]) & 1    // MP 内 2 个 L2 slice
```

L1D/L2 的组号采用 XOR 散列（削弱 warp 内组冲突）：

```
// L1D（32 组）：
l1set = ((A>>7) ^ (A>>13) ^ (A>>19)) & 0x1F
// L2 slice（128 组）：
l2set = ((A>>7) ^ (A>>14) ^ (A>>21) ^ (mp<<2)) & 0x7F
```

### 7.2 通道内 DRAM 地址

```
byte_in_burst = A[4:0]            // 32B atom
col  = A[11:5]                    // 列（每次突发 32B）
bank = (A[14:12] ^ A[18:16] ^ (mp[2:0])) & 0b111
row  = {A[31:19], A[15]?} —— 裁定：row = A[35:15]（去掉 bank/col 位后紧缩）
```

物理 DRAM 总容量 6 GiB 时地址位宽到 35；功能模型按稀疏字典存储，无需真实行阵列。

## 8. 片上互连 NoC

- 16 个 NSM 端口 + 6 个 MP 端口的全交叉开关；每端口每周期收发各 1 个 flit。
- flit：8 字节负载。包 = 1 头 flit + 若干数据 flit：
  - 读请求/原子：1 头；写请求：1 头 + ⌈字节数/8⌉（32B=4）；读响应：1 头 + 4（sector）；行填充 1 头 + 16。
- 头 flit 字段：`{type(REQ/RSP/ATOM/INV), src, dst, addr, mp, slice, subid, sectors, cmd, n_flit, gen}`。
- 2 条虚通道：REQ（每输入口 4 flit 缓冲）、RSP（4）；响应不得被请求队头阻塞。
- 仲裁：输入/输出端各一个 RR 分配器，周期内求最大匹配（仿真器用贪心即可：按端口号 RR 扫描不冲突对）。
- 时序：路由+仲裁 1 周期（router pipe），链路 1 周期/flit；端到口注入延迟按 flit 数自然累加。
- 模型简化：无流控反压死锁（缓冲够深）；缓冲满时发送方 replay/等待（记 `noc_backpressure`）。
- 功能模型：NoC 是函数 `send(pkt)`，直接调用 MP 逻辑并同步返回（顺序保持：同 slice 内请求顺序 = 到达顺序）。

## 9. Memory Partition：L2 slice

每 MP 2 slice；每 slice 独立 tag/data 阵列，**入站请求按到达顺序处理**（顺序模型）。

参数：128 KiB/slice、8 路、128B line/4×32B sector、128 组、LRU、64 MSHR/slice。

处理：

1. 按 §7.1 入 slice；MSHR 合并同 line。
2. 读命中：返回所需 sector（响应包）。
3. 读缺失：入 FB 调度器（§11），数据回填 slice（置位返回的 sector 有效位）并回 NSM。
4. 写（WT 穿通透写）：
   - 整 sector 被字节使能全覆盖的写缺失：**不读 DRAM**，直接写入/分配并置全 sector 有效（教材 4.3.1）；
   - 部分覆盖的写缺失：取旧 sector（RFO）后合并；
   - 命中：直接合并；脏行在替换时才写 DRAM（写数据在等待期间驻留 L2 行内，不另设大 SRAM）。
5. 替换：LRU；脏（曾被 local/写回数据弄脏）行进入本 slice 的写队列。
6. 原子：命中/回填后交 ROP（§10）；原子未完成前，同 line 其他 MSHR 不得放行（顺序点）。

延迟名义值（含 NoC 往返，00 册配置）：L2 命中回 RF 180 拍；DRAM 路径 400 拍起，竞争排队由模型自然增加。

---

## 10. ROP 原子单元

每 MP 1 个：1 个原子 ALU（ADD/MIN/MAX/CAS/逻辑等，32/64 位）+ 2 KiB 原子操作 cache（最近热行）。

- 同一 MP 内对同一 line 的原子在 ROP **严格串行**；命中原子 cache 时不必重复 L2 阵列读。
- CAS 语义：读出旧值→比较→条件写，返回旧值；整个序列对其他 MP 不可见中间态（L2 MSHR 顺序保证）。
- 不同地址/行可流水（每 2 拍接收 1 个原子，执行 4 拍）。
- shared 空间原子不经过 ROP（§2.3）。

## 11. FB 访存调度器（每通道）

GDDR5 通道前的请求重组接口包含行缓冲状态和请求队列。1.1 的通道完成时间由资源预约表维护。

结构：

- **read sorter**：按 (bank,row) 组相联查找的小表，每个在途行一个指针；
- **read request store**：各挂一个读请求链表（节点 = slice 发来的读/原子读）；
- **write queue**：脏行/整行写，挂在 L2 行内等待，单独 FIFO；
- 调度策略 **FR-FCFS**：

```
每周期（通道可发起一条新命令时）：
1) 若存在已 ACTIVE 行的待服务请求（行命中）→ 优先服务之（先读后写）
2) 否则服务最老的读请求：必要时 PRE 旧行 → ACTIVE 新行（tRP+tRCD）→ CAS
3) 写仅在下列情形服务：读队列空，或自上次排空写以来已服务 write_drain_threshold=32 个读
4) 写之后在 tWR + tRP 后才能同一 bank 再读
```

## 12. 【F】GDDR5 通道时序状态机

每通道 8 bank，每 bank 独立行缓冲；通道命令/数据总线全 bank 共享。

配置时序（ns，@1 GHz 下 1ns≈1 周期换算；tCK 用于突发长度）：

| 符号 | 值(ns) | 含义 |
|---|---|---|
| tCK | 0.4 | 传输时钟 |
| tBURST | 1.6 | 32B atom 占数据总线时间（4 次传输） |
| tRCD | 12 | ACTIVE→读/写 |
| tCAS(CL) | 12 | 列读到数据出 |
| tRP | 12 | PRECHARGE |
| tRAS | 28 | ACTIVE 后最短才能 PRE |
| tRC | 40 | ACTIVE→ACTIVE 同 bank |
| tWR | 12 | 写恢复 |

bank 状态机：

```
IDLE  --ACTIVATE(row)--> ACTIVING(12) --> ACTIVE
ACTIVE --READ(col)--> READING(tCAS) → 数据总线占用 tBURST → 回 ACTIVE
ACTIVE --WRITE(col)--> WRITING(入数据 tBURST) → tWR → ACTIVE
ACTIVE --PRE(需 ACTIVE 已维持 ≥tRAS)--> PRECHG(tRP) --> IDLE
```

约束（每个硬件模拟器必须检查）：

- 同 bank 命令间隔 tRC；ACTIVE 后未满 tRAS 不得 PRE；
- 数据总线是全局资源：任意 bank 的 tBURST 不得重叠（总线竞争排队是吞吐主因）；
- 行命中（请求行==当前 ACTIVE 行）只付 tCAS+tBURST；行缺失付 tRP+tRCD+tCAS；
- 刷新：基线不建模刷新（在统计中注明）；EXT-REFRESH 可选 7.8 µs 间隔。
- 带宽自洽性校验：单通道峰值 = 32B / 1.6ns = 20 GB/s；6 通道 = 120 GB/s。

【F】功能模型：每次读返回存储内容、每次写修改内容；原子即时串行完成；无延迟、无错误。

## 13. 内存顺序模型与栅栏实现

- 基线为**弱序**：同一线程的访问可在存储系统中被重排，但有以下硬约束：
  1. 同一 slice 内请求按入站顺序处理（§9）；
  2. ROP 对同行原子串行；
  3. 同一 warp 的依赖链由 NSM 记分牌保证（地址/数据未就绪不发射后继）。
- LSU 维护两个在途计数（每 warp）：
  - `vmem`：已发出未完成的 global/L2 路径事务数；
  - `smem`：在途 shared 事务数（shared 很快，但 replay 期间也算在途）。
  LD/ST/ATOM 发射时递增，响应/完成时递减。
- `MEMBAR.CTA`：等到 smem==0 且本 warp 此前 global 写已进 L2（vmem 中写类事务==0）才放行；
  `MEMBAR.GL`：等到 vmem==0（全部 global 事务拿到 L2 及以下确认）；
  `MEMBAR.SYS`：GL + host 可见（功能模型相同）。
- `BAR.SYNC` 释放前追加：本 CTA 全部到达 warp 的 smem==0（shared SRAM 天然可见）；global 可见性仍需程序自行 MEMBAR。
- L1D 不互保一致（§4.5），所以 GL 栅栏**不刷对方 L1**；可写共享数据走 L2 是程序员责任（只读推断/编译器 hint）。

## 14. 存储侧统计

每 NSM：`smem_accesses`、`smem_conflict_replays`、`l1_access_lines/sectors`、`l1_miss_sectors`（分 global/local）、`l1_assoc_stall`、`prt_full`、`wdb_full`、coalescing 效率（`sectors_out / (32*accesses)`）、const 广播率、I-cache miss。
NoC：`flits_sent`、`noc_stall_cycles`、每端口占用率。
L2：`l2_access/hit/miss`（按 slice）、`alloc_no_read`（整 sector 写免读次数）、原子数。
DRAM：`reads/writes`、`row_buffer_hit/miss`（行命中率）、`bank_busy_cycles`、`bus_busy_cycles`、读/写队列平均深度、`bytes_to_dram/from_dram`、有效带宽 GB/s。

## 15. 功能模拟器存储实现清单（最小集合）

1. 五个空间各一个字节数组/稀疏映射 + flat 窗口路由（§3、00 册 §6）；
2. shared 按 CTA 分区（§2）；
3. coalescing 只影响**性能模型输入**：功能模拟器可直接按 lane 逐字节 load/store（保留 §3.1 第 4 步的同址写决胜规则，功能结果必须一致）；
4. global 读写即时对所有后续 kernel/拷贝可见；L1 概念不存在；
5. 原子按全局锁（或按字哈希锁）串行，CAS 语义精确；
6. 屏障计数与栅栏计数（即时归零即放行）；
7. 越界/对齐错误按第 02 册 §6 返回错误码。
